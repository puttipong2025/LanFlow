# แผนชุดจ่ายรวมรายการโอนเงิน

สถานะ: ดำเนินการครบและตรวจสอบผ่านใน Local; ยังไม่ migrate Cloud/commit/push/deploy  
วันที่: 2026-10-16

## เป้าหมาย

ทำให้ผู้ใช้รวมงานค้างเพื่อจ่ายได้ทุกช่วงเวลา โดยยังรักษารายการลูก ต้นทาง สลิปเดิม และ Report Lock ไว้ครบถ้วน รองรับสองชุดที่แยกจากกันเสมอ:

1. ชุดโอนเงินลูกค้า — ลูกค้าเดียวกัน บัญชีเดียวกัน และสาขาเดียวกัน
2. ชุดค่าทำงาน REX — รายการค่าทำงานส่งออกยางของสาขาเดียวกัน

## โครงสร้างที่เล็กที่สุด

- ใช้ `money_transfers` เดิมเป็นแถวแม่ของชุด
- เพิ่มความสัมพันธ์จากรายการลูกกลับไปยังแถวแม่
- ใช้ `money_transfer_slips` เดิมเก็บสลิปที่เพิ่มผ่านชุด
- ไม่สร้างตารางชุดใหม่
- ไม่สร้างตารางจัดสรรยอดใหม่ในรุ่นแรก
- คำนวณการจัดสรรแบบ FIFO จากรายการลูกเก่าไปใหม่ด้วยกติกาฝั่ง Server เดียวกันทุกจุด

## การสร้างและสมาชิก

### ชุดลูกค้า

- เปิดจาก route โอนเงินเดิม
- คงช่องค้นหา/เลือกลูกค้าและ dropdown บัญชีแบบเดียวกับรายการลูก
- เมื่อเลือกแล้ว ระบบแสดงและรวมรายการ `pending` กับ `partial` ที่เข้าเงื่อนไขจากทุกช่วงเวลา
- รวมเฉพาะรายการที่มี `customer_id` จริงและเลขบัญชีตรงกัน ห้ามจับคู่จากชื่อข้อความ
- แสดงจำนวนรายการที่ข้ามพร้อมเหตุผล เช่น ยังไม่ผูกลูกค้าหรือไม่มีบัญชี
- ถ้ามีชุดปลายทางเดียวกันที่ยังไม่มีสลิปและไม่ถูกล็อก ให้ใช้ชุดเดิมและเพิ่มสมาชิกแทนการสร้างชุดซ้ำ

### ชุดค่าทำงาน

- รวมรายการค่าทำงาน REX ที่ `pending` หรือ `partial` ของสาขา
- ไม่เพิ่มชื่อผู้รับหรือบัญชีใหม่ เพราะชุดสะท้อนข้อมูลจากรายการลูก
- ไม่ปะปนกับชุดลูกค้า

สมาชิกเป็น snapshot ณ ตอนสร้างหรืออัปเดตชุด รายการที่เกิดภายหลังไม่เข้าชุดอัตโนมัติ หลังมีสลิปของชุดใบแรกแล้วห้ามเปลี่ยนลูกค้า บัญชี หรือสมาชิก

## หน้ารายการ

ใช้ตาราง route โอนเงินเดิม ไม่เพิ่มหน้าใหม่และไม่ใช้ wizard

- เพิ่มตัวกรองเล็ก ๆ: `ทั้งหมด | รายการเดี่ยว | ชุดจ่ายรวม`
- ชุดลูกค้าแสดงชื่อลูกค้า ธนาคาร/เลขท้ายบัญชี จำนวนรายการลูก ยอดตั้งต้น จ่ายเดิม จ่ายผ่านชุด และคงเหลือ
- ชุดค่าทำงานแสดงว่าเป็นชุด REX จำนวนรายการลูก ช่วงเลข REX และยอดเดียวกัน
- หนึ่งชุดนับเป็นงานค้างหนึ่งรายการในตาราง badge และ Telegram; รายการลูกที่ซ่อนห้ามนับซ้ำ
- รายการลูกยังค้นย้อนหลังและเปิดดูผ่านรายละเอียดชุดได้

## หน้ารายละเอียดชุด

ใช้ modal เดียวในหน้าเดิม เรียงเนื้อหาจากบนลงล่าง:

1. หัวชุด — รหัสชุด ประเภท สถานะ ผู้สร้าง เวลา และสถานะ Report Lock
2. สรุปยอด — ยอดตั้งต้น จ่ายเดิม จ่ายผ่านชุด และยอดคงเหลือ
3. รายการลูก — เรียงเก่าไปใหม่ แสดงต้นทาง ยอดเดิม จ่ายเดิม ยอดที่ได้รับจากชุด และคงเหลือ
4. สลิปเดิมของรายการลูก — อ่านอย่างเดียวและยังเป็นของรายการลูกเดิม
5. สลิปของชุด — เพิ่ม อ่านสลิป แก้ หรือลบได้ตามสถานะและ Report Lock
6. แถบคำสั่งด้านล่าง — คัดลอกข้อมูล ยุบชุด บันทึก และปิด

ทุกแถวรายการลูกมีปุ่มรูปดวงตา:

- ลูกค้า: เปิดรายละเอียดต้นทางของรายการโอนเดิม และแสดงจำนวนบิลถ้ามีหลายใบ
- ค่าทำงาน: เปิดรายละเอียด REX เดิม
- หน้ารายละเอียดเป็นแบบอ่านอย่างเดียว เปิดซ้อนเหนือ modal ชุด และเมื่อปิดต้องกลับตำแหน่งเดิม

## การจ่ายและปุ่มคัดลอก

- สลิปใหม่หนึ่งใบเป็นของชุดหนึ่งใบ ไม่คัดลอกเป็นหลายสลิป
- จัดสรรยอดจากรายการลูกเก่าสุดไปใหม่สุด และไม่จัดสรรเกินยอดคงเหลือของแต่ละรายการ
- ส่วนเกินทั้งหมดอยู่ที่ชุดและทำให้ชุดเป็น `overpaid`
- ชุดลูกค้ามีปุ่มคัดลอกบัญชีและคัดลอกยอดคงเหลือแบบเดิม
- ชุดค่าทำงานมีปุ่มคัดลอกยอดคงเหลือเท่านั้น
- ชุดลูกค้ามีตัวเลือก “สาขาจ่ายส่วนที่เหลือ” โดยระบบคำนวณยอดสาขาจ่ายจากยอดคงเหลือปัจจุบัน ไม่มีช่องกรอกยอดเอง
- เมื่อเปิด “สาขาจ่ายส่วนที่เหลือ” ให้ปิดปุ่มคัดลอกยอดเพื่อป้องกันโอนซ้ำ
- ชุดค่าทำงานไม่มีตัวเลือกสาขาจ่ายส่วนที่เหลือ

## สถานะและ Report Lock

- `pending` และ `partial`: ยังแก้สลิปได้และห้าม Report Lock
- `paid` และ `overpaid`: เป็นสถานะสิ้นสุดและเข้า Report Lock ได้
- `branch_and_transfer`: ใช้เฉพาะชุดลูกค้าและเข้า Report Lock ได้
- รายงานแสดงชุดสิ้นสุดหนึ่งแถว พร้อมเปิดดูรายการลูก สลิป และการจัดสรร แต่ไม่แสดงรายการลูกซ้ำเป็นแถวการเงิน
- การที่เอกสารต้นทางของรายการลูกถูก Report Lock ไม่ขวางการนำรายการโอนที่ยังไม่ถูกล็อกเข้าชุด
- ห้ามลดหรือถอด Report Lock กลางระบบเพื่อให้รวมชุดได้

## การแก้และยุบชุด

- ระหว่างอยู่ในชุด รายการลูกเป็นแบบดูอย่างเดียว: ห้ามแก้ ลบ หรือเพิ่มสลิปตรงที่รายการลูก
- ถ้าต้องแก้รายการลูก ต้องยุบชุดก่อน
- ยุบได้เมื่อชุดยังไม่มีสลิปของชุดและยังไม่ถูก Report Lock
- การยุบลบเฉพาะตัวชุด/ความสัมพันธ์ และทำให้รายการลูกกลับมาแสดงในงานค้าง
- ห้ามลบรายการลูก สลิปเดิม หรือต้นทางเมื่อยุบชุด

## กติกาอ่านสลิปและปุ่มบันทึก

ใช้พฤติกรรมเดียวกันในสามฟอร์มของ route โอนเงิน:

1. โอนจ่ายสาขา
2. โอนเงินลูกค้า
3. จ่ายค่าขนส่ง

เมื่อเริ่มอ่านสลิป ปุ่ม `บันทึก` ต้อง disabled โดยผูกกับสถานะกำลังอ่านสลิปโดยตรง ไม่อาศัยเพียงการที่ยังไม่มีสลิป เมื่อ OCR สำเร็จหรือล้มเหลวจึงปลดล็อกตาม validation ปกติ ปุ่มยกเลิกยังใช้ได้เพื่อออกจากฟอร์ม และผล OCR ที่กลับมาหลังปิดฟอร์มต้องไม่ทำให้เกิดการบันทึกหรือแก้ state ที่เลิกใช้งานแล้ว

## เกณฑ์ยอมรับหลัก

- รวม `pending` และ `partial` ได้ทุกช่วงเวลาโดยไม่ย้ายหรือลบต้นทาง
- ชุดลูกค้าไม่รวมข้ามลูกค้า บัญชี หรือสาขา
- ชุดค่าทำงานไม่รวมกับลูกค้าและไม่มีสาขาจ่ายส่วนที่เหลือ
- ยอดชุดเท่ากับผลรวมยอดคงเหลือ ไม่ใช่ผลรวมยอดตั้งต้น
- รายการลูกและสลิปเดิมไม่ถูกนับซ้ำในรายการ งานค้าง หรือรายงาน
- หลังสลิปแรก สมาชิกถูกตรึงและการจัดสรร FIFO ให้ผลเหมือนกันทุกจุด
- ยุบชุดแล้วรายการลูกกลับมา และข้อมูลเดิมไม่สูญหาย
- ชุดที่ยังไม่สิ้นสุด Report Lock ไม่ได้
- ระหว่าง OCR ปุ่มบันทึกของทั้งสามฟอร์มกดไม่ได้ แม้ฟอร์มมีสลิปหรือข้อมูลที่ครบอยู่ก่อนแล้ว

## ผลการดำเนินงาน (2026-10-16)

- ใช้ `money_transfers` parent + `bundle_parent_id` + `is_payment_bundle` ตาม ADR และเพิ่ม `bundle_frozen_at` เพื่อจำการเริ่มจ่ายอย่างถาวร โดยไม่มีตาราง bundle/allocation ใหม่
- รองรับ customer และ REX work แยกชุด, FIFO ฝั่ง Server, child/source/slip read-only, search child คืน parent, filter รายการเดี่ยว/ชุดรวม, badge/Telegram ไม่ซ้ำ และ dissolve คืนรายการลูก
- UI อยู่ใน route เดิม มี dropdown ลูกค้า/บัญชี, candidate preview, summary, child eye, สลิปลูกอ่านอย่างเดียว, bundle OCR/slips, copy account/balance และ customer-only branch remainder
- Report รับเฉพาะ terminal bundle เป็นหนึ่งแถวและเปิดดูรายการลูก สลิปลูก สลิปชุด และยอดจัดสรรจาก detail RPC เดียวกัน
- Save ของ branch/customer/transport และ bundle ถูกล็อกระหว่าง OCR
- หลักฐาน: migration replay ผ่าน, DB lint ผ่าน, pgTAP 1,151 tests ผ่าน, isolated 519 tests ผ่าน, TypeScript/ESLint/source-size/import checks/build/PWA/Service Worker/bundle budget ผ่าน
- visual browser automation ถูกปิดใน Work settings จึงใช้ accessibility contract, responsive source review และ production render/build เป็น gate แทน; ยังควรทำ manual visual smoke ก่อน deploy
- ไม่มี Cloud migration, commit, push หรือ deployment ในรอบนี้
