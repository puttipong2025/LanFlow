# ล้างทะเบียนรหัสเครื่องและนำรหัสกลับมาใช้ใหม่

ผู้ใช้ยืนยันเริ่มงานเมื่อ 2026-11-02 ให้ reset ล้างทะเบียนรหัสเครื่องบน Cloud รวมรหัสที่เคยใช้ และนำรหัสกลับมาจัดสรรจาก D01 ใหม่ โดยคงเลขบนบิลเก่าและงานค้างไว้ ข้อตกลงนี้แทนที่แนวทางเก็บทะเบียนและไม่วนรหัสใน ADR0100

ผู้ใช้เลือกให้นับเลขท้ายต่อเมื่อเลขฐานตรงกับบิลเดิม เช่น ภายในสาขาและชุดเลขบิลเดียวกัน บิลเก่า `0001-261102-D01-1` และบิลใหม่ `0001-261102-D01-2` จึงนำรหัสเครื่องและเลขฐานกลับมาใช้ได้โดยไม่ทำให้เลขบิลเต็มซ้ำ และการส่งบิลเดิมซ้ำยังต้องได้เลขเดิม

ผู้ใช้เลือกให้เครื่องที่ยังออฟไลน์ระหว่าง reset ออกบิลด้วยรหัสเดิมต่อได้จนกลับมาติดต่อส่วนกลาง จากนั้นลงทะเบียนรับรหัสอีกครั้ง ส่วนบิลค้างและงานรออนุมัติคงเลขเดิมและส่งต่อได้ตามสิทธิ์ หากฐานตรงกับบิลจากเครื่องที่ได้รับรหัสซ้ำ ให้ส่วนกลางจัดสรรเลขท้ายแยกตามกติกาข้างต้น ไม่บังคับออนไลน์ก่อนออกบิลทุกครั้ง

ผู้ใช้เลือกให้เครื่องที่ลงทะเบียนหลัง reset เริ่มลำดับบิลใหม่จาก `0001` โดยยังแยกตามสาขา ประเภท และวัน เลขท้ายจากส่วนกลางไม่เริ่มใหม่เมื่อมีฐานเดิมอยู่แล้ว

ขอบเขตที่คงจาก ADR0100: ใช้กับทะเบียนทุกสาขาร่วมกันสำหรับบิลยางและรับ–จ่าย เฉพาะ Super Admin พิมพ์ “รีเซ็ตทั้งหมด” และยืนยันชุดทะเบียนก่อนดำเนินการ การลองคำสั่งเดิมซ้ำต้องคืนผลเดิมและไม่ล้างเครื่องที่ลงทะเบียนหลังคำสั่งนั้นสำเร็จ ไม่แก้ข้อมูลธุรกิจหรือ Auth

คำว่าไม่เก็บรหัสเก่าหมายถึงล้างทะเบียนรหัสเครื่องรวมรายการที่เลิกใช้แล้ว ไม่ล้างเลขที่อยู่บนบิล งานค้าง หรือหลักฐานกันเลขบิลซ้ำและการส่งซ้ำตามข้อตกลงข้างต้น ปัจจุบันตัวตรวจเลขบิลยังอาศัยทะเบียนเดิม จึงลบทะเบียนอย่างเดียวแล้วคงงานค้างให้ส่งได้โดยไม่ปรับสัญญาไม่ได้ การออกแบบต้องรองรับบิลเดิม งานออฟไลน์ และงานรออนุมัติที่ยังอ้างทะเบียนซึ่งถูกล้าง

## การรักษาบิลเดิมโดยไม่เก็บทะเบียนเก่า

เก็บเฉพาะ SHA-256 ของ issuer UUID + สาขา + รหัส ในตารางหลักฐานตรวจเลขบิลส่วนตัว ไม่เก็บ UUID รหัสเครื่อง การติดตั้ง รุ่นเบราว์เซอร์ หรือผู้ใช้เป็นช่องข้อมูลในตารางนี้ ตัวตรวจเลขเดิมยังบังคับรูปแบบ เลขฐาน สาขา และข้อมูลที่เปลี่ยนย้อนหลังไม่ได้ แต่ตรวจบิลค้างจาก digest แทนทะเบียนที่ถูกล้าง รหัสหรือ UUID ที่สร้างขึ้นใหม่เองไม่ผ่าน การล้างทะเบียนซ้ำไม่ล้างหลักฐานเหล่านี้

เพิ่มรอบทะเบียนที่เพิ่มขึ้นทุกครั้งที่ reset โดยไม่เริ่มนับรอบใหม่ เครื่องจึงรับ D01 จากรอบใหม่ได้แม้รหัสเดิมสูงกว่า และปฏิเสธคำตอบลงทะเบียนจากรอบเก่าที่มาช้า ลำดับบิลใหม่เริ่มต้นเมื่อ UUID ของทะเบียนสาขาเปลี่ยน ส่วนรายการจองและคำสั่งเก่ายังคงเดิม

Forward migrations: `20261102010000_clear_bill_device_registry.sql` และ `20261102011000_bill_device_clear_safeupdate.sql` ต้องติดตั้งครบคู่ ตัวหลังเพิ่ม WHERE ที่ชัดเจนให้การล้างทะเบียนผ่าน safeupdate ของ PostgREST การติดตั้งเพิ่ม schema/ฟังก์ชันเท่านั้น ไม่เรียก reset อัตโนมัติ หลักฐานและขั้นตอนตรวจอยู่ [verification ledger](../bill-device-code-reuse-verification.md)

ผลตรวจ Business/Route เพิ่ม `20261102012000_bill_device_reset_mode_contract.sql` และ `20261102013000_guard_legacy_bill_device_reset.sql` จึงต้องติดตั้งทั้งสี่ไฟล์ก่อนเปิด UI ใหม่นี้: preview/request/receipt ต้องระบุ `clear_registry_v1` และ mutation ใช้ RPC สี่พารามิเตอร์ที่ตรวจ mode ซ้ำ RPC สามพารามิเตอร์ของเว็บเก่าใช้ตรวจผลคำสั่งที่สำเร็จแล้วได้เท่านั้น ป้องกันทั้งเว็บใหม่ที่เจอฐานข้อมูลเก่าและเว็บเก่าที่เจอฐานข้อมูลใหม่ โดยไม่เพิ่ม preview RPC ใน POST ดู [scan ledger](../bill-device-code-reuse-route-scan-20261102.md)

ตอนปล่อยจริงต้องพัก execute ของ RPC สามพารามิเตอร์จาก authenticated ก่อนเริ่มลงชุด migration แล้วคืนหลังตรวจว่า guard สุดท้ายติดตั้งแล้ว เพื่อไม่ให้เว็บเดิมเรียก implementation ระหว่างทาง รายละเอียดคำสั่งและการกู้เมื่อ migration หยุดกลางทางอยู่ใน scan ledger ไม่กระทบการลงทะเบียนเครื่อง/ส่งบิล/Auth และยังไม่ได้ทำขั้นตอนนี้บน Cloud
