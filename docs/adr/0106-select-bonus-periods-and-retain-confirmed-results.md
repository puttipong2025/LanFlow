# เลือกช่วงประเมินโบนัสเองและเก็บผลที่ยืนยันหลังล้างข้อมูล

> ปรับขอบเขต 2026-11-04: flow ใหม่รวม REX ที่ยังไม่ใช้ทั้งหมดของสาขาโดยบังคับ ไม่เลือกออกทีละใบ รวมรายการกำลังดำเนินการเพื่อตรวจจนทุกใบเป็นประวัติ/ลดน้ำหนักจริง แยกรับกลับสาขาเดิมและรายการตกค้างในช่วงโบนัสเดิมตามกติกา แบ่งช่วงไม่คร่อมผลเดิมให้อัตโนมัติ ตั้งค่าแยกช่วงและยืนยันทุกช่วงในธุรกรรมเดียว คงค่าใช้จ่ายจริงของ A → A ตามคำยืนยัน การเก็บ snapshot และ history lock เดิมยังมีผล ดู `docs/branch-bonus-contract.md`

> ปรับข้อตกลงภายหลังเมื่อ 2026-11-03: ส่วนการเลือกช่วงประเมินเองถูกแทนด้วยช่วงอัตโนมัติจากวันที่สร้างต่ำสุดถึงวันที่สร้างมากสุดของ REX ที่เลือก ตาม `docs/branch-bonus-design.md` ผู้ใช้ยืนยันให้ใช้วันที่ที่แสดงใต้เลข REX ตามเวลาไทย ไม่ใช่วันยืนยัน ส่วนการเก็บผลที่ยืนยันไว้หลังล้างต้นทางใน ADR นี้ยังมีผล

> ขอบเขตเพิ่มเติมที่ใช้จริง: เลือกได้เฉพาะ REX ในประวัติ เมื่อยืนยันผลโบนัสสำเร็จแล้ว REX ที่เลือกออกจากประวัติไม่ได้จนลบผลโบนัส รวมการล้างแบบ TRUNCATE ดังนั้นการเก็บ snapshot หลังต้นทางหายไม่ใช่สิทธิ์ข้ามกฎนี้ ข้อมูลต้นทางประเภทอื่นที่ล้างได้ยังไม่ลบผลโบนัสตามไปด้วย การคำนวณใหม่ต้องตรวจความครบ ดูสัญญาและผลทดสอบจริงใน `docs/branch-bonus-contract.md` และ `docs/branch-bonus-verification.md`

รายการโบนัสยังประเมินก้อนรวมสำหรับสาขาเดียว แต่เจ้าของเลือกวันเริ่มต้น–สิ้นสุดเองได้โดยไม่ต้องต่อจากรายการก่อนหน้า เพราะข้อมูลธุรกิจอาจถูกล้างในอนาคต หลังล้างยังเปิดดูผลโบนัสที่ยืนยันแล้วได้ โดยเก็บช่วงข้อมูล ตัวเลขที่ใช้ ค่าใช้จ่ายที่ยกเว้น สูตรและค่าตั้ง รวมถึงยอดที่ยืนยันไว้ ส่วนการคำนวณใหม่ทำได้เฉพาะช่วงที่ข้อมูลยังครบ จึงไม่ต้องเก็บคลังข้อมูลรายละเอียดสำหรับคำนวณช่วงที่ล้างแล้ว

ข้อตกลงนี้แทน ADR 0104 เรื่องการต่อช่วงอัตโนมัติ และ ADR 0105 เรื่องการลบผลโบนัสตามข้อมูลอ้างอิง โดยยึดคำตอบข้อ 1 ในการสนทนาว่า “ดูผลโบนัสเก่าได้ แต่คำนวณใหม่ได้เฉพาะช่วงที่ข้อมูลยังครบ” ช่วงข้อมูลขาดต้องแสดงว่าข้อมูลไม่ครบแทนการตีความเป็นยอดศูนย์

รายละเอียดวัน/เวลา ช่วงที่ซ้อนกัน และรายการออฟไลน์ที่มาภายหลังที่ยืนยันเพิ่มเติมอยู่ใน `docs/branch-bonus-design.md` การเก็บผลหลังล้างต้นทางยังอนุญาตให้ผู้ใช้ลบรายการโบนัสที่ทำผิดเพื่อเริ่มใหม่โดยไม่เก็บประวัติยกเลิกตามข้อกำหนดแยกต่างหาก ยังไม่พัฒนาฟังก์ชันหรือดำเนินการล้างข้อมูล
