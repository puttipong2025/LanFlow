# Generate searchable business PDFs in the browser

Status: Accepted

LanFlow generates Report Batch, Rubber Export, payroll-slip, and withdrawal-slip PDFs in the browser from their detail API responses. Each feature keeps its own presentation model and columns while sharing only the A4 constants, local Noto Sans Thai font loading, PDF `ActualText`, page lifecycle, footer, and in-memory file creation. Report Batch and Rubber Export use A4 landscape; payroll and withdrawal slips use A4 portrait. `ActualText` preserves the logical Thai text used by search, selection, copy, and assistive technology even when glyph shaping uses a different visual order.

The generated PDF exists only as an in-memory `Blob` and `File`. When the browser supports file sharing, LanFlow calls Web Share with the PDF file and a human-readable title. Otherwise it creates a temporary object URL, downloads the same file, reports the fallback to the user, and revokes the URL. The application does not upload, persist, or add a database record for the generated file.

Report Batch uses `buildReportPresentation` as the shared semantic model for its in-app preview and PDF. The report-list action opens the preview before sharing, loads the detail response once per opening, and creates the PDF from that same in-memory `ReportDetails` object without refetching at share time. The preview is a continuous document: full-screen on mobile, a large dialog on desktop, and wide tables retain their columns with horizontal scrolling. Loading and detail errors remain inside the dialog; sharing is available only after detail loading succeeds, and a successful share or fallback download leaves the preview open.

The layout uses manual row measurement so a row is never split across pages, repeats table headers after page breaks, and adds the document number plus `หน้า X/Y` to every page. Report Batch always shows both rubber-bill groups, with records assigned from the current customer class and unknown customers placed in the farmer group. Deleted Report Batch and Rubber Export documents remain shareable as historical copies marked `ลบแล้ว (สำเนา)`; a deleted Rubber Export also carries its previous status, deletion audit, and a low-contrast watermark.

Payroll and withdrawal slips use one presentation model for both the in-app preview and PDF, so labels, ordering, status, and calculated values stay aligned. They are available only while the source row exists, is not cancelled, and has status `PENDING` or `APPROVED`; unlike historical Report Batch and Rubber Export documents, deleted or rejected payroll/withdrawal sources have no PDF. Access relies on the existing source-row RLS rather than a second document permission. Payroll monetary, calendar, and transaction data come from `slip_data`; its current approval/payment metadata is overlaid at read time. Withdrawal calendar and wage values are calculated live from existing time segments, the database paid-day function, deduction ledger, and source `remaining_amount`, without creating a snapshot or stored file.

Server-side Chromium rendering was rejected because it adds infrastructure and stored-artifact concerns without improving this workflow. Raster or canvas PDFs were rejected because their content cannot be reliably searched or copied. Rendering the Report Batch PDF from preview HTML was also rejected because it would couple paper pagination to the responsive screen layout. Rubber Export's former `/rubber-exports/[exportId]/print` route and payroll's former `/slip/[id]` route were removed; their in-app surfaces now fetch detail data and share the PDF directly. The separate legacy Report Batch print route remains for internal compatibility and is not linked from the report-list UI.
