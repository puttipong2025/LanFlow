# Reference real sources from money-transfer items

Money-transfer items reference exactly one rubber bill or OCR ticket through a real foreign key with restricted deletion, while the existing source type and source ID remain synchronized for compatibility with current reports and locks. Existing rows are backfilled only when their source exists; migration stops on an orphan or mismatch instead of deleting or guessing test data. Receipt source details are loaded online through a read-only RPC that checks the active user, money-transfer-module permission, and transfer-location access, and a missing source is treated as an invariant violation rather than producing a reduced receipt. This adds two nullable source columns and a compatibility trigger, but it makes referential integrity enforceable by the database without rewriting every existing consumer in the same change.
