# Replace time segments with standard workdays and exceptions

LanFlow will calculate payroll attendance from a system-wide standard of one full paid day for every Bangkok calendar day, bounded by each employee's current payroll start, end, and pause state. Managers edit each employee's calendar individually to record half-day or unpaid-day exceptions, including future exceptions; returning a date to full day removes its exception. This replaces the operational role of start/stop time segments, the 15:00 cutoff, automatic month-start resume, and calendar snapshot restore because those mechanisms no longer represent how payroll is operated.

The product has one operating mode: exception attendance. The retirement migration is fail-closed when it finds an open timer segment or a pending month-resume schedule, then fixes the settings constraint and default to `EXCEPTIONS`, unschedules timer jobs, and removes authenticated access to legacy timer writers. Historical segment rows remain intact and readable only by existing slip/report compatibility paths; they are not backfilled, cleared, or exposed as an alternate mode. Dropping the legacy tables and readers requires a separate verified archive migration after Cloud data has been checked.

The employee table has one `จัดการ` column for all row actions. Its calendar/overview, daily-wage, and payroll actions are emoji-only buttons with action-specific accessible names. The former `แดชบอร์ด` and `สรุปสิ้นเดือน` action columns are removed; the calendar/overview action opens the same employee workspace and therefore does not duplicate a second dashboard control.

One global Time/Payroll Config defines only the Bangkok workday end time at minute precision. The migration inserts and activates `16:00` on its Bangkok deployment date; there is no unconfigured or legacy fallback state, and existing employees do not accrue earlier days. Later changes take effect on the next Bangkok day, with at most one replacement pending value. The page shows no history, but changes remain in the central Admin audit. The end time gates when full and half days enter projected wage; values are computed from server time on demand rather than materialized by a daily job.

Attendance exceptions are locked by a pending or approved Payroll Slip, not by Report Batch or by approved debt/withdrawal adjustments. Branch managers may edit an employee's attendance calendar directly within primary-branch scope without approval; each save has event audit but no restore snapshot or generic approval record. The 15:05 daily deduction invocation from ADR-0027 is superseded. Approved debts and withdrawals affect projected net pay with one shared rule and reuse the existing deduction ledger only during payroll close; excess adjustments carry forward and may make projected net pay negative. No daily wage or deduction entry is generated.
