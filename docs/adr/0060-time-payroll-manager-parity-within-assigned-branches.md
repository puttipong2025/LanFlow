# ให้ Admin ที่ได้รับสิทธิ์เวลาและเงินเดือนจัดการได้เท่าผู้จัดการระบบภายในสาขาที่ดูแล

ผู้ใช้ต้องการให้ Admin ที่เปิดสิทธิ์เวลาและเงินเดือนมีอำนาจจัดการเท่าผู้จัดการระบบเฉพาะงานเวลาและเงินเดือนและสาขาที่ตนดูแล การออกแบบนี้ปรับจาก ADR-0048 ซึ่งกำหนดให้รายการที่ผู้จัดการประจำสาขาสร้างรอส่วนกลางอนุมัติ เพื่อให้ผู้ได้รับมอบหมายดำเนินงานในขอบเขตของตนได้ครบวงจร

## ข้อสรุปที่ยืนยันแล้ว

- ผู้ใช้ยืนยันว่าอำนาจนี้รวมการอนุมัติหนี้ เงินเบิก และสลิปของตนเองด้วย
- หนี้ เงินเบิก และสลิปที่ Admin กลุ่มนี้สร้างภายในขอบเขตได้รับอนุมัติทันทีเช่นเดียวกับรายการที่ผู้จัดการระบบสร้าง และสามารถตัดสินรายการรออนุมัติภายในขอบเขตได้
- ขอบเขตยึดสาขาหลักของพนักงานซึ่งต้องอยู่ในสาขาที่ Admin ดูแล รวมกรณีพนักงานเจ้าของรายการเป็น Admin ผู้ดำเนินการเอง พร้อมเก็บประวัติผู้ดำเนินการ
- สิทธิ์นี้จำกัดอยู่ในงานเวลาและเงินเดือน ไม่เปลี่ยนบัญชีให้เป็นผู้จัดการระบบ
- Config เวลาสิ้นสุดวันทำงานยังเป็นค่าเดียวร่วมทั้งระบบ แต่ผู้ใช้เปลี่ยนกติกาให้เฉพาะ super admin แก้ไขได้ ผู้จัดการระบบและ Admin ที่ได้รับสิทธิ์เวลาและเงินเดือนดูได้อย่างเดียว
- การจำกัด Config เป็นข้อยกเว้นจากความเท่าเทียมของสิทธิ์จัดการรายบุคคล เพราะการแก้ค่าร่วมมีผลกับทุกสาขา โดยลดสิทธิ์แก้ Config เดิมของผู้จัดการระบบด้วย
- ผู้ใช้ยืนยันให้ Admin กลุ่มนี้เลือกผู้จ่ายเงินเบิกหรือเงินเดือนได้เฉพาะสาขาที่เปิดใช้งานและตนดูแล หรือ “ส่วนกลางจ่ายนอกระบบ” ซึ่งไม่สร้างรายจ่ายในสาขาใด ขอบเขตผู้จ่ายต้องตรวจแยกจากสาขาหลักของพนักงาน
- ผู้ใช้ยืนยันให้คงขอบเขตบัญชีเป้าหมายเดิม: จัดการได้เฉพาะ User และ Admin ที่เปิดใช้งานและมีสาขาหลักที่เปิดใช้งานอยู่ในสาขาที่ตนดูแล รวมตนเองและ Admin ที่ได้รับสิทธิ์เวลาและเงินเดือนคนอื่น แต่ห้ามจัดการ super admin และผู้จัดการระบบแม้มีสาขาหลักอยู่ในขอบเขต
- ผู้ใช้ยืนยันว่ารายการเก่าของพนักงานในขอบเขตซึ่งอนุมัติและลงรายจ่ายไว้ในสาขาที่ Admin ไม่ได้ดูแลยังดูได้ แต่ลบหรือเปลี่ยนวิธีจ่ายไม่ได้ ให้ผู้จัดการระบบหรือ super admin จัดการตามกฎล็อกเดิม การย้ายไปส่วนกลางจ่ายไม่ใช่ข้อยกเว้นให้ข้ามสิทธิ์ของสาขาผู้จ่ายเดิม
- ผู้ใช้กำหนดให้ทำแบบง่ายและแก้โครงสร้างให้น้อยที่สุด ใช้บทบาท สิทธิ์เวลาและเงินเดือน สาขาหลัก และข้อมูลผู้จ่ายเดิม
- ผู้ใช้เพิ่มงาน UI: เปิด modal วิธีจ่ายเมื่อกดอนุมัติ และแสดงว่าสาขาใดจ่ายใกล้ปุ่ม “เปลี่ยนวิธีจ่าย”

## แบบสรุปสำหรับลงมือ

ภายในขอบเขตพนักงานและผู้จ่ายข้างต้น Admin ที่ได้รับสิทธิ์ใช้คำสั่งงานเวลาและเงินเดือนเดิมได้เท่าผู้จัดการระบบ ได้แก่ แก้วันทำงานและค่าแรง เปิด พัก กลับมา หรือสิ้นสุดเงินเดือน จัดการกำหนดการและแก้วันเริ่มตามเงื่อนไขเดิม สร้างหนี้ เงินเบิก และสลิป อนุมัติหรือปฏิเสธรายการ รวมถึงลบและเปลี่ยนวิธีจ่ายเมื่อกฎสถานะและ Report Lock อนุญาต การอนุมัติของตนเองใช้ขอบเขตเดียวกับการจัดการคนอื่น

งานนี้คงวิธีคำนวณ วันมีผล กฎการปิดเดือน การหักและคืนยอด ลำดับสลิป และ Report Lock เดิม บันทึกการกระทำใช้ Audit เดิม ส่วนหน้าประวัติแอดมินส่วนกลางคงสิทธิ์ผู้จัดการระบบและ super admin ตามเดิม เพื่อไม่เพิ่มงานสร้างระบบ Audit แยกรายสาขา

## เพิ่มงานหน้าต่างวิธีจ่าย

- ใช้หน้าต่างจาก `ExpenseLocationChangeModal` เดิมร่วมกันสำหรับอนุมัติและเปลี่ยนวิธีจ่าย แยกเพียงข้อความหัวข้อ ช่องวิธีจ่าย และปุ่มยืนยันให้ตรงกับการกระทำ โหมดอนุมัติใช้ปุ่ม “อนุมัติ” โหมดแก้รายการเดิมใช้ “บันทึก” ไม่สร้าง UI ชุดที่สาม
- เงินเบิกและสลิปที่มียอดสุทธิมากกว่าศูนย์เปิดหน้าต่างเมื่อกดอนุมัติ ให้ดูยอดแบบอ่านอย่างเดียว เลือกสาขาในขอบเขตหรือส่วนกลางจ่าย และกรอกหมายเหตุแบบไม่บังคับ จากนั้นส่งการอนุมัติพร้อมวิธีจ่ายในคำสั่งเดียว
- การปิดหรือยกเลิกไม่อนุมัติและไม่เปลี่ยนรายการ หากบันทึกไม่สำเร็จให้คงหน้าต่างกับข้อมูลที่กรอก พร้อมแสดงข้อผิดพลาด หนี้และสลิปที่ไม่มียอดจ่ายคงขั้นตอนอนุมัติเดิมโดยไม่เลือกผู้จ่าย
- ใกล้ปุ่ม “เปลี่ยนวิธีจ่าย” ของทั้งเงินเบิกและสลิป แสดง “จ่ายโดย: <ชื่อสาขา>” หรือ “ส่วนกลางจ่าย (จ่ายนอกระบบ)” ตามค่าปัจจุบันที่ระบบบันทึกไว้ ข้อความยังอ่านได้เมื่อรายการถูกล็อกหรือผู้ใช้ไม่มีสิทธิ์เปลี่ยน และอัปเดตหลังบันทึกสำเร็จ
- อ่านชื่อสาขาผู้จ่ายของรายการเก่าตามสิทธิ์อ่านรายการ แม้สาขานั้นไม่อยู่ในตัวเลือกสาขาที่ผู้ใช้แก้ได้ ไม่ใช้ชื่อสาขาหน้าจอหรือสาขาหลักแทน และไม่ตีความการโหลดชื่อไม่สำเร็จว่าเป็นส่วนกลางจ่าย
- รักษา `ModalShell` เดิม ชื่อกำกับช่องกรอก การใช้ Tab/Escape และการคืนโฟกัสไปยังปุ่มที่เปิดหน้าต่าง จัดข้อความวิธีจ่ายกับปุ่มให้อยู่กลุ่มเดียวกันทั้งจอเล็กและจอใหญ่

ข้อเท็จจริงจาก source: `handleApprove` เปิด `ExpenseLocationApprovalModal` แยกจาก `ExpenseLocationChangeModal` อยู่แล้วสำหรับเงินเบิกและสลิปยอดบวก แต่รายการแสดงชื่อวิธีจ่ายเฉพาะส่วนกลาง ส่วน `PayrollModal.createSlip` ส่งเพียงพนักงานกับเดือนและยังไม่มีขั้นตอนเลือกวิธีจ่ายก่อนสร้าง จึงมีประเด็นให้ยืนยันเพิ่มเติมสำหรับการสร้างที่อนุมัติทันที

## แนวทางแก้ขั้นต่ำ

1. ใช้ `can_manage_time_payroll` และ `private.can_manage_time_payroll_profile` เดิมเป็นฐานตรวจสิทธิ์รายบุคคล ปรับเฉพาะ API/RPC/RLS ที่ยังบังคับผู้จัดการระบบสำหรับคำสั่งในขอบเขตนี้ และคงความหมายของสิทธิ์ผู้จัดการระบบส่วนกลางไว้
2. เพิ่ม forward migration เพื่อปรับฟังก์ชันและนโยบายเดิมให้ตรวจสาขาพนักงานกับสาขาผู้จ่ายแยกกัน ตรวจผู้จ่ายเดิมก่อนลบหรือเปลี่ยนวิธีจ่าย และตรวจผู้จ่ายใหม่ก่อนสร้างรายจ่าย ไม่เพิ่มตาราง คอลัมน์ บทบาท toggle หรือระบบสิทธิ์ชุดใหม่
3. ปรับหน้าเดิมและข้อมูลสิทธิ์จาก API ให้เปิดปุ่มตามคำสั่งที่ทำได้ กรองพนักงาน งานรออนุมัติ และ badge ตามขอบเขต แยกสิทธิ์แก้ Config ส่วนกลางซึ่งมาจากบทบาท super admin ออกจากสิทธิ์แก้ค่าแรงและช่วงเงินเดือนรายบุคคล ใช้ modal วิธีจ่ายเดิมร่วมกันและคืนชื่อสาขาผู้จ่ายของแต่ละรายการเพื่อแสดงใกล้ปุ่ม
4. ปรับ tests สิทธิ์เดิมและเพิ่มเฉพาะกรณีขอบเขตที่เปลี่ยน พร้อมตรวจชนิดข้อมูลและ build แล้วปรับเอกสารกติกาที่ขัดกันให้ตรงกับข้อสรุปนี้

## การตรวจรับที่จำเป็น

- Admin ที่ได้รับสิทธิ์ทำคำสั่งเดิมในขอบเขตได้ รวมตนเองและ Admin ที่ได้รับสิทธิ์คนอื่น รายการที่สร้างอนุมัติทันที และรายการรออนุมัติตัดสินได้
- API/RPC/RLS ปฏิเสธพนักงานนอกสาขาหลักที่ดูแล บัญชีผู้จัดการระบบหรือ super admin และหยุดสิทธิ์จัดการเมื่อถอน toggle หรือเปลี่ยนขอบเขตสาขา
- ปฏิเสธการเลือกสาขาจ่ายใหม่ที่อยู่นอกขอบเขต และการลบหรือเปลี่ยนวิธีจ่ายของรายการที่มีรายจ่ายเดิมนอกขอบเขต แม้ปลายทางเป็นส่วนกลางจ่าย
- เฉพาะ super admin แก้ Config ได้ ทั้งหน้าเว็บ API และฐานข้อมูล ผู้จัดการระบบกับ Admin ที่ได้รับสิทธิ์ยังอ่านได้
- คงกฎ Report Lock การหักและคืนยอด การย้ายสาขาหลัก และสิทธิ์โมดูลอื่น ตรวจด้วยชุดทดสอบที่เกี่ยวข้องโดยตรง
- กดอนุมัติเงินเบิกหรือสลิปยอดบวกต้องเปิด modal วิธีจ่ายก่อน ยกเลิกแล้วข้อมูลไม่เปลี่ยน ยืนยันแล้วอนุมัติพร้อมผู้จ่ายตามที่เลือก และไม่ส่งคำสั่งซ้ำระหว่างบันทึก
- ข้อความผู้จ่ายใกล้ปุ่มตรงกับข้อมูลหลังอนุมัติหรือเปลี่ยนวิธีจ่าย รวมส่วนกลาง สาขาเก่านอกขอบเขต และรายการที่ถูกล็อก พร้อมตรวจคีย์บอร์ดและการคืนโฟกัส

## สถานะการนำไปใช้

นำไปใช้แล้วด้วย forward migrations `20260903030000`–`20260903050000` โดยไม่เพิ่มตาราง คอลัมน์ role หรือ toggle ใหม่ API แยกสิทธิ์แก้ Config ออกจากสิทธิ์จัดการรายบุคคล และ UI ใช้ `ExpenseLocationChangeModal` ร่วมกันสำหรับสร้าง อนุมัติ และเปลี่ยนวิธีจ่าย รายการที่สร้างและมียอดจ่ายเปิด modal เลือกผู้จ่ายก่อนคำสั่ง atomic create-and-approve ส่วนยอดศูนย์สร้างและอนุมัติได้โดยไม่ถามผู้จ่าย

การตรวจรับ Local ผ่าน pgTAP 39 ข้อ, browser/API regression ของสิทธิ์ การจ่าย focus และจอแคบ, database lint, TypeScript และ production build รายละเอียดอยู่ใน `docs/reviews/time-payroll-manager-parity.md` กติกาเก่าใน ADR-0048 ถูกแทนที่เฉพาะส่วน approval ของ delegated Admin ส่วน employee self-service ยังรออนุมัติตามเดิม
