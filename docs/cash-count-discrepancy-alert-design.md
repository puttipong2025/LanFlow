# แจ้งเตือนส่วนต่างจากผลนับล่าสุด

สถานะ: พัฒนาและตรวจรับแล้ว ใช้ migration บน Cloud วันที่ 2026-10-27 ตามคำสั่งผู้ใช้ โดยกลุ่มเดิมยังปิดเกณฑ์ส่วนต่าง หลักฐานอยู่ใน `docs/cash-count-discrepancy-alert-verification.md`

## กติกาที่ตกลง

- ตั้งค่าในกลุ่มเกณฑ์นับเงินเดิม ใช้จำนวนเดียวร่วมกันทั้งเงินขาดและเงินเกิน เข้าเกณฑ์เมื่อขนาดส่วนต่างมากกว่าจำนวนที่ตั้งไว้ ไม่รวมกรณีเท่ากันพอดี
- ค่าว่างปิดการแจ้งเตือนส่วนต่าง ศูนย์บาทแจ้งทุกส่วนต่างที่ไม่เป็นศูนย์ รับจำนวนไม่ติดลบ ทศนิยมไม่เกินสองตำแหน่ง กลุ่มเดิมเริ่มเป็นค่าว่าง
- ดูเฉพาะรายการนับล่าสุดที่ยังไม่ถูกลบของแต่ละสาขา ผลนับใหม่แทนผลเก่า ไม่ย้อนเลือกครั้งเก่าที่เกินเกณฑ์ขณะที่มีครั้งใหม่แล้ว
- ยืนยันตรวจสอบแล้วก็ยังแจ้งต่อหากส่วนต่างล่าสุดเกินเกณฑ์ การตรวจไม่ได้เปลี่ยนจำนวนเงิน
- แจ้งเตือนอย่างเดียว ไม่เพิ่มเงื่อนไขล็อก และไม่เปลี่ยนการเริ่มรอบกำหนดวันหลังนับสำเร็จ

## การแสดงผลที่ผู้ใช้ระบุ

- ช่องตั้งค่าอยู่ในฟอร์มเดิม `space-y-3 rounded-md bg-field p-3`
- แจ้งเตือนนับเงินอยู่ภายในกรอบกลุ่ม `rounded-md border border-black/10 p-3`
- เกณฑ์ส่วนต่างแสดงในหัวกรอบกลุ่มภายใน `flex flex-wrap items-baseline justify-between gap-2` เช่น “เกณฑ์ขาด–เกิน: มากกว่า 100.00 บาท” ไม่แสดงเกณฑ์ซ้ำในแถวสาขา
- รวมเงื่อนไขที่แจ้งของสาขาเดียวกันไว้ในแถวเดียว `flex items-start justify-between gap-4 rounded-md bg-field px-3 py-2.5` หากเข้าเงื่อนไขมากกว่าหนึ่งข้อให้เพิ่มรายละเอียดภายในแถวนั้น ไม่สร้างแถวสาขาซ้ำตามจำนวนเงื่อนไข
- ตัวอย่างรายละเอียด: ชื่อสาขา, เกินกำหนดกี่วันเมื่อเข้าเงื่อนไข, ผลนับล่าสุดขาดหรือเกินกี่บาทเมื่อเข้าเกณฑ์ พร้อมวันเวลานับ เพื่อให้แยกความหมายของวันกับจำนวนเงินชัดเจน

## ขอบเขตเอกสาร

เอกสารนี้บันทึกข้อกำหนดและสัญญาที่ตรวจแล้ว ผู้ใช้สั่ง commit/push main และ Cloud migration แยกวันที่2026-10-27 แล้ว การยืนยันผล rollout ของ hosting และทดสอบอุปกรณ์จริงเป็นคนละขั้นตอนกับ Git/DB

## สัญญาที่ใช้ในการพัฒนา

- ใช้ count candidate เดียวต่อสาขา เพิ่ม optional ส่วนต่างภายใน โดยไม่เพิ่ม AlertKind หรือตัวนับต่อเงื่อนไข
- เลือกผล active ล่าสุดตาม created_at DESC,id DESC เหมือนประวัติ ส่วน cutoffAt ใช้แสดงเวลานับและกติกากำหนดวันเดิมไม่เปลี่ยน
- omitted field คงเกณฑ์เดิม; explicit null ล้าง; 0 เปิดทุกส่วนต่าง ใช้ RPC8อาร์กิวเมนต์พร้อม flag การแก้ โดย RPC3/6อาร์กิวเมนต์เดิมคงค่า
- รวมข้อมูล count/lock เป็นแถวสาขาก่อน render ไม่ซ่อนส่วนต่างเมื่อมีสถานะล็อก
- ใช้ mutation/storage event และรอบตรวจเดิม: refresh เงียบไม่เปิดหน้าต่างที่รับทราบแล้ว และทิ้งคำตอบเก่าที่ถูก invalidate ระหว่างรอ
- Scope ของแจ้งเตือนยังเป็นทุกสาขาที่ผู้ใช้มีสิทธิ์ตามระบบเดิม การเลือกสาขาบนหัวแอปไม่เปลี่ยน scope นี้; การเปลี่ยนผู้ใช้/บทบาท/ขอบเขตสิทธิ์ยังยกเลิกคำขอเดิม
