# Rubber numbering business/route scan — 2026-10-31

Local scan of the current numbering, issuer routes, outbox, core validation and receipt call graph. No Cloud change or deployment. The goal is to preserve one local base allocation and stable central finals while rejecting damaged state and malformed boundary inputs.

## Simpler-alternative pass

Keep the existing registry, queue, suffix allocator, error protocol and recovery path. Tightening their current guards is smaller than adding a numbering version, another queue or a new error subsystem. Framework route exports are entry points, not unused functions.

## Ranked hypotheses and trace

- Damaged allocator readiness: (1) `validState` checks reservation types/counter but not the actual base; (2) cached registration forces readiness true; (3) the outbox itself was corrupted; (4) the fixture issuer/root is invalid. Repro changes only `reservations[id].base`; the frozen outbox remains valid. V8 debugger stops in `validState` with code D01 and base `damaged` while readiness returns true. The unchanged old-layout/counter continuation and healthy parallel-save controls distinguish this from cache/fixture errors.
- Retirement false failure: (1) case-sensitive UUID acknowledgement comparison; (2) a different issuer acknowledged; (3) permissions rejected the action; (4) no committed acknowledgement. Repro returns a valid canonical ID and `retired:true`; V8 debugger observes uppercase requested ID versus lowercase acknowledgement, followed by 503. Lowercase success and wrong-issuer rejection are the disproof controls.
- Permanent metadata failure: (1) PostgreSQL casts escape before the stable numbering error; (2) calendar failure is transient; (3) permission or missing registry; (4) the queue response validator loses a valid success. pgTAP observes SQLSTATE 22008 for February 30 and 22P02 for malformed UUID, while all 39 existing healthy numbering cases pass. The queue Route only binds `INVALID_BILL_NUMBER`/`BILL_NUMBER_CHANGED`; other RPC errors return 503 and the uploader backs off/retries. No PL/pgSQL debugger extension is installed, so the trace follows the native casts and Route/uploader branches.
- Registry bounds: (1) SQL NULL makes the page guard unknown and LIMIT NULL unbounded; (2) API always supplies 20, masking the direct RPC path; (3) permissions stopped the call. Authenticated-manager pgTAP observes no exception for explicit NULL limit; ordinary-admin denial still passes. The API also admits offsets outside its PostgreSQL integer argument range.
