# Bill device reset — Business/Route scan (2026-11-01)

Scope: the recently implemented bill-device bulk reset, its registration/management Route seams and validators. Intent is to preserve the exact confirmed device set and original command while changing only the shared registration lifecycle. The smaller approach reuses the existing validation primitives and receipt/retry paths; no new API, schema, queue or abstraction is needed.

## Reproductions and hypothesis ledger

1. Read the new Route/contract/UI and installed SQL through to unchanged registration and numbering paths. `tsc --noEmit --noUnusedLocals --noUnusedParameters` passed. Call-site searches found no unused runtime function, variable or import in the feature scope. Exported wire types are used by type predicates; they are not unused runtime code.
2. Added regression assertions before changing product code. Focused Routes: **4 failed / 44 passed**. Three malformed completion dates (`"1"`, date-only, February 30) returned HTTP200 instead of503; registration acknowledged a different branch with HTTP200 instead of503. Valid timestamp/microsecond/offset and case-insensitive matching-branch controls passed.
3. Completion-date candidates: permissive JavaScript date parsing; malformed request accepted before RPC; response body substituted by the harness. Exact valid request and two valid response controls disprove the latter two as explanations. Attached V8 inspector to the actual transpiled contract: Date.parse reports finite values for the invalid examples. First breakpoint used an exact URL while vm resolved a file URL, so it did not pause; retry used a filename regex. Existing `validation/primitives.ts` already owns calendar-correct ISO timestamp and UUID checks, so reuse it instead of adding another validator.
4. Registration candidates: UUID casing mismatch; only shape checked after RPC; browser allocator accepting a wrong branch. The uppercase request/matching lowercase response control passes and the browser persistence already checks branch identity. The Route's structural validator lacks the request/response branch equality check. Add only that semantic check, preserving UUID case-insensitive equivalence.
5. Browser regression against dedicated test Supabase: an actual reset commits, then the intercepted response is an unrelated409 (`OTHER_CONFLICT`). Existing UI discards request/preview and loads a new preview rather than keeping its original request as uncertain. The test fails waiting for the original-command retry button. Competing explanations: any409 treated as reset conflict; reset never committed; requestId regenerated by backend. The interception asserts the real backend returned200 before altering the client response; receipt requestId comes from the unchanged submitted body. Thus only the status-only UI branch explains loss of the original client command. The existing real reset-specific409 scenario is the differential control.

6. Debugger setup correction: the contract has two `return uuid(...)` lines (request and receipt). Early breakpoints accidentally selected the request predicate and therefore never paused during a receipt call. Used the parsed script ID and the `count(v.retiredCount)` line to pause at the actual receipt validation boundary; invalid completion dates and the valid-date control all reached this predicate with finite Date.parse results. No debug probes were added to production source.
