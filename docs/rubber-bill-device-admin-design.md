# เลขบิลยางและทะเบียนเครื่อง — แบบที่นำมาทำ

วันที่: 2026-10-31 · สถานะ: พัฒนาและตรวจรับในเครื่องแล้ว ยังไม่ได้เปิดใช้ Cloud

ข้อตกลงล่าสุดแทนข้อเสนอเดิมที่เลขเต็มคงเดิมก่อนและหลังซิงก์: device ออกเลขฐาน `0015-261031-D03` ครั้งเดียว ส่วนกลางเติมเลขท้ายเมื่อสร้างบิลสำเร็จเป็น `0015-261031-D03-1` คนละบิลที่ฐานตรงกันได้ `-2` และ retry ของบิลเดิมได้เลขเดิม ดู ADR 0091 และ `docs/rubber-device-numbering-verification.md`

ย้ายลำดับรายวันมาไว้หน้าอย่างเดียว ไม่รีเซ็ตตัวนับหรือเปลี่ยนรหัสเครื่อง เช่น เคยออก `2610310015-D03` บิลใหม่ถัดไปเป็น `0016-261031-D03` บิลและคิวเก่าคงเลขเดิม

## หน้าจอและ PDF

ใช้ช่อง `เลขที่บิล` เพียงช่องเดียว ก่อนยืนยันส่วนกลางแสดงฐานพร้อมสถานะรอเลขท้าย หลังยืนยันแสดง final ไม่เพิ่มเลขอ้างอิงบนเครื่องอีกชุด PDF ที่แชร์ออฟไลน์ยังเป็นฉบับฐานตามที่ออกจริง ผู้ใช้พิมพ์ฉบับ final ภายหลังเอง ไม่มี auto-share ซ้ำ การมีฐาน/การรับเข้าคิวไม่ใช่การอนุมัติหรือบันทึกการเงินสำเร็จ

## Admin → เครื่องออกบิล

ใช้ Admin เดิมและสิทธิ์เดิม เฉพาะ Super Admin/ผู้จัดการระบบดูทะเบียนและเลิกใช้งาน code ได้ ตารางมี code สาขา browser/platform ผู้ใช้ล่าสุด เวลาเริ่มใช้/ติดต่อล่าสุด สถานะและผู้เลิกใช้ พร้อมกรองสาขา/สถานะ ค้นหาและแบ่งหน้า เวลา last seen ไม่ใช่สถานะออนไลน์จริง และ browser/profile ไม่ใช่เครื่อง hardware

ปุ่มเลิกใช้เปิด confirmation ด้วย ModalShell เดิมแบบ alertdialog แสดงเป้าหมายให้ชัด ป้องกันกดซ้ำ แสดงข้อผิดพลาดในจุดทำงาน และเปลี่ยนสถานะหลัง acknowledgement ที่ตรง code เท่านั้น เก็บทะเบียนและ audit actor/time ไม่ลบข้อมูลเดิมหรือถอน login

## รหัสเครื่องและความต่อเนื่อง

ส่วนกลางแจก D01 ขึ้นไป ไม่วนหรือคืนรหัส หลายแท็บ/บัญชีใน browser/profile+สาขาเดิมใช้รหัสและลำดับร่วมกัน แต่เจ้าของบิล/ร่าง/คิว/สิทธิ์ยังแยกตามบัญชี ถ้ารหัส/ตัวนับจำเป็นหายต้องออนไลน์รับ registration ใหม่ ไม่เริ่มนับด้วย code เก่า

หลัง retire เครื่อง offline ยังใช้ code เก่าจนรู้สถานะ เมื่อ reconnect และยังมีสิทธิ์จะรับ code ใหม่สำหรับบิลใหม่ บิลเดิม/งานค้างรักษาฐานและ final เดิม ไม่ rewrite payload ที่เคยส่ง

## ขอบเขต

เฉพาะบิลเครื่องชั่งเล็กใหม่ manual/OCR บิลเก่าและรายการรับยางจากสาขาคงวิธีเดิม วันที่ฐานยึดวันที่บิลตอนรับไว้ครั้งแรก ไม่เปลี่ยนเมื่อแก้วันที่ภายหลัง ไม่คืนลำดับหลังยกเลิก/ลบ เลขสุดท้ายไม่ซ้ำภายในสาขา แต่ฐานบนเอกสาร offline อาจซ้ำจากข้อมูลย้อนคืน/โคลน ซึ่งแก้ด้วย suffix หลังซิงก์ ไม่แอบเปลี่ยนเอกสารที่ส่งแล้ว
