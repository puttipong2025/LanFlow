# รายละเอียดสลิปเงินเดือนเมื่อมีหนี้

ข้อกำหนดล่าสุด: ผู้ใช้ให้เอาบรรทัด “หักรวมเดือนนี้” ออกจากสรุปทุกสลิป ทั้ง Preview และ PDF โดยคงการคำนวณและยอดสุทธิเดิม สลิปไม่มีหนี้เหลือค่าแรงรวมกับเงินเดือนสุทธิ ส่วนสลิปมีหนี้คงรายละเอียด ยอดก่อนหัก และยอดค้างไว้ ข้อนี้แทนข้อกำหนดเดิมด้านล่างที่ให้แสดงยอดหักในสรุป

สถานะ: Local implemented and verified 2026-11-01; ยังไม่ apply Cloud หรือ deploy

## ข้อตกลงที่ยืนยันแล้ว — 2026-10-31

- ปรับวิธีแสดงรายละเอียดบนสลิปให้อ่านเข้าใจง่าย โดยคงกติกาคำนวณและหักหนี้เดิม
- แยกเงินเดือนสุทธิที่ต้องจ่ายออกจากหนี้คงเหลือ เพื่อไม่ให้ผู้อ่านเข้าใจว่าหนี้คงเหลือถูกหักซ้ำ
- ตัวอย่างที่ยืนยัน: ค่าแรง 10,000 บาท มีหนี้ 15,000 บาท หักชำระหนี้เดือนนี้ 10,000 บาท เงินเดือนสุทธิที่ต้องจ่าย 0 บาท และหนี้คงเหลือยกไปเดือนถัดไป 5,000 บาท
- เงินเดือนสุทธิที่ต้องจ่ายเป็นยอดตามสลิป ไม่ใช่การรับรองว่าพนักงานได้รับเงินจริงแล้ว
- ผู้ใช้ต้องการสลิปที่กระชับ เข้าใจง่าย และมีรายละเอียดรายการที่เคยกรอกประกอบด้วย ไม่ใช่แสดงเฉพาะยอดรวม
- ผู้ใช้ต้องการเพิ่มรายละเอียดจากตัวอย่างแบบย่อเล็กน้อย และให้ยอดสรุปอยู่ด้านล่างของสลิปหลังรายละเอียดรายการ
- แสดงรายการหนี้และเงินเบิกพร้อมประเภท วันที่ รายละเอียดที่เคยกรอก และจำนวนเงิน โดยไม่แสดงยอดหักหรือยอดค้างแยกรายการ
- สรุปค่าแรงรวม หนี้และเงินเบิกก่อนหักรวม หักรวมเดือนนี้ ยอดค้างยกไปเดือนถัดไป และเงินเดือนสุทธิที่ต้องจ่ายเพียงครั้งเดียวด้านล่าง
- ใช้รูปแบบและถ้อยคำเดียวกันทั้งหน้าดูสลิปและไฟล์ PDF ตามที่ผู้ใช้ยืนยัน
- หนี้และเงินเบิกจากเดือนก่อนใช้ยอดยกมาที่ยังเหลือ พร้อมวันที่และรายละเอียดเดิม เช่น หนี้เดิม 6,000 บาท เคยหักแล้ว 4,000 บาท ให้แสดงหนี้ยกมา 2,000 บาท ไม่แสดง 6,000 บาทเป็นยอดที่จะหักในเดือนนี้
- ยืนยันเพิ่มเติม 2026-11-01: สลิปที่ไม่มีหนี้หรือเงินเบิกใช้สรุปเพียงค่าแรงรวม หักรวมเดือนนี้ 0 บาท และเงินเดือนสุทธิที่ต้องจ่าย ซ่อนรายละเอียดหนี้ที่ว่าง รวมถึงบรรทัดยอดก่อนหักและยอดค้างที่เป็นศูนย์ ทั้ง Preview และ PDF
- สลิปที่มีหนี้/เงินเบิกหรือยอดหักยังแสดงสรุปเต็มตามเดิม แม้ยอดค้างหลังหักเป็นศูนย์ ไม่ใช้ยอดหักเป็นศูนย์เพียงอย่างเดียวตัดสินว่าปลอดหนี้

## ขอบเขตการปรับ

- คงข้อมูลเอกสาร สถานะ ผู้สร้าง/ผู้อนุมัติ วิธีจ่าย ปฏิทินวันทำงาน และช่องลายเซ็นเดิม
- แยกข้อมูลวันทำงานและค่าแรงต่อวันไว้เหนือรายละเอียด ส่วนสรุปทางการเงินอยู่ด้านล่างเพียงแห่งเดียว
- คงรูปแบบสลิปเบิกเงินเดิม
- ไม่เปลี่ยนยอดเงิน วิธีหักหนี้ วิธีจ่าย สิทธิ์ หรือกฎ Report Lock

## หลักฐาน implementation

- `src/lib/time-tracking/slip-document.ts`: ใช้ `workSummary` แยกข้อมูลค่าแรงจากสรุปยอด และแสดงรายละเอียดจาก `outstandingSources` โดยลบ `deductionRows` ที่ไม่มีผู้ใช้ออกแล้ว เพื่อไม่ให้เก็บยอดหักกับยอดค้างซ้ำ
- `src/components/time-tracking/SlipPreviewModal.tsx` และ `src/lib/time-tracking/slip-pdf.ts`: ข้อมูลเอกสาร → ข้อมูลค่าแรง → ปฏิทิน → รายละเอียดหนี้/เงินเบิก → สรุปยอด → หมายเหตุและลายเซ็น
- `supabase/migrations/20261031044000_payroll_slip_outstanding_source_details.sql`: เพิ่มข้อมูลประกอบใน `slip_data.outstandingSources` ตอนสร้างสลิป โดยใช้วันที่และรายละเอียดต้นทาง ยอดก่อนหักเดือนของสลิป และธงยอดยกมา
- การคำนวณข้อมูลประกอบใช้จุดเวลาเดียวกับ outstanding snapshot เดิม รวมยอดปรับเงินเบิกที่มีผล ณ เวลานั้น และไม่นำรายการอนุมัติภายหลังหรือยอดหักเดือนถัดไปมาเปลี่ยนสลิปย้อนหลัง
- Backfill เปลี่ยนเฉพาะข้อมูลประกอบของสลิปเก่าที่ตรวจยอดรายละเอียดแล้วตรงกับยอดก่อนหักเดิม โดยรักษารายละเอียดที่มีอยู่ในสลิป และใช้ข้อยกเว้นชั่วคราวของ Report Lock กับ dashboard trigger ใน transaction ของ migration ตามรูปแบบ migration outstanding เดิม
- สลิปเก่าที่ข้อมูลต้นทางไม่ครบใช้รายละเอียดที่เคยบันทึกไว้แทน ไม่เดายอดยกมาหรือแก้ยอดรวมย้อนหลัง

## การตรวจสอบ

- Database regression: 221 assertions ผ่าน ครอบคลุมยอดยกมา ข้อมูลต้นทาง ยอดปรับย้อนหลัง สิทธิ์ helper และ payment/branch-balance contract เดิม
- Isolated payroll regression: 39 tests ผ่าน
- Document API และ money contract: 16 tests ผ่าน
- Browser/PDF: 5 tests ผ่านหลังปรับรอบสุดท้าย ตรวจทั้งแชร์/ดาวน์โหลด PDF ค้นหาข้อความได้ หน้าเดียว 80 มม. รายการยาว 49 รายการ และมือถือกว้าง 360 px; ยอดหักกับยอดค้างไม่ซ้ำและสรุปอยู่หลังรายละเอียด
- ตรวจภาพ `output/pdf/LanFlow-payroll-debt-clarity-render.png` และภาพมือถือแล้ว ข้อความและตัวเลขอ่านครบ ไม่ซ้อนหรือถูกตัด
- TypeScript, ESLint, source-size, import-direction, local DB lint และ diff check ของไฟล์ในงานนี้ผ่าน
- Production build, Service Worker check และ bundle budget ผ่าน
- Full DB suite: 76 files / 1,863 assertions มี 1 failure นอกขอบเขตใน `rubber_central_queue_test.sql` ข้อ 42 (`execution delay does not expire the admitted edit window`): ได้ `pending_approval` แทน `synced`; ทดสอบแยกซ้ำและปิด trigger ใหม่ของ payroll ชั่วคราวใน transaction แล้วยังได้ failure เดิม จึงไม่แก้คิวบิลยางในงานนี้ ทุกชุดเวลา/เงินเดือนผ่าน
- Local migration `20261031044000` apply แล้ว และ `supabase-schema.sql` สอดคล้องกับ catalog ที่เพิ่มขึ้น ไม่มี Cloud write, commit, push หรือ deploy

ยังไม่มีการตัดสินใจเชิงสถาปัตยกรรมที่แก้กลับได้ยาก จึงยังไม่สร้าง ADR สำหรับการเปลี่ยนถ้อยคำและการจัดข้อมูลนี้
