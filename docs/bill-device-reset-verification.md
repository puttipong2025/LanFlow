## Final scrutiny

Intent: retire all active shared device registrations on explicit Super Admin confirmation, preserving every issued number and queued business command. The smaller design reuses `AlertDialog`, existing role auth, the current register/retire lifecycle and polling; it adds no allocator, queue, realtime channel or IndexedDB version.

Traced `AdminContent → RubberBillIssuers → BillDeviceReset → role/origin/input validation → RPC receipt replay → exclusive registry gate → deterministic active-device snapshot → atomic device/link retirement + receipt → checked acknowledgement`. Followed unchanged registration back through the shared gate/per-installation lock and browser persistence; old numbering validators retain retired registrations and legacy references, with real business/approval tests on both sides of reset.

Conflict uses PT409; timeouts/uncertain responses keep the original request rather than broadening the target set. Metadata/branch-link changes under one device do not invalidate its identity snapshot; replacement identities do. No remaining blocking finding in the feature scope. Verdict: **ship-ready locally**, with Cloud rollout separate. No commit/push/deploy in this task.
