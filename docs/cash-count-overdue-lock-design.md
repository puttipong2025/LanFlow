# ล็อกงานการเงินเมื่อเกินกำหนดนับเงิน

สถานะ: พัฒนาและตรวจรับใน local แล้ว ใช้ migration บน Cloud วันที่ 2026-10-26 ตามคำสั่งผู้ใช้ โดยค่าเริ่มต้นยังปิดล็อกทุกกลุ่ม ดูผลตรวจใน `docs/cash-count-overdue-lock-verification.md`

## ข้อตกลงที่ยืนยันแล้ว

- ล็อกเฉพาะการเพิ่ม แก้ไข และลบรายการที่กระทบยอดเงินของสาขา ยังดูข้อมูล นับเงิน และเปิดแจ้งเตือนได้
- ล็อกและปลดล็อกระดับสาขา ใช้เงื่อนไขเดียวกันทุกคน ไม่แยกช่วงอนุญาตตามบัญชีหรือเบราว์เซอร์
- Super Admin และผู้มีสิทธิ์ผู้จัดการระบบปลดล็อกได้ รวมถึงสาขาตัวเองแม้ตนอยู่ภายใต้ล็อกนั้น
- เมื่อปลดล็อก ทุกคนที่มีสิทธิ์เดิมในสาขาใช้ช่วงอนุญาตเดียวกัน การปลดล็อกไม่เพิ่มสิทธิ์เข้าถึงสาขา
- ข้อตกลงล่าสุดยกเลิกข้อเสนอเดิมที่ผู้จัดการระบบซึ่งถูกล็อกต้องรอ Super Admin และข้อเสนอปลดล็อกเฉพาะบัญชี+สาขา
- ตั้งระยะเวลาสองค่ารายกลุ่มเกณฑ์นับเงินเดิมในฟอร์มเดียวกัน: ผ่อนผันก่อนล็อก 1–48 ชั่วโมง และใช้งานได้หลังปลดล็อก 1–48 ชั่วโมง โดยช่วงหลังเริ่มจากเวลาที่กดปลดล็อก
- เริ่มชั่วโมงผ่อนผันที่ 00:00 น. ของวันถัดจากวันครบกำหนดตามเวลาไทย เช่น ครบกำหนดวันที่ 26 ต.ค. และผ่อนผัน 8 ชั่วโมง จะล็อกวันที่ 27 ต.ค. เวลา 08:00 น. หากยังไม่มีผลนับสำเร็จ
- ผู้จัดการระบบปลดล็อกได้ทุกสาขาที่ตนมีสิทธิ์เข้าถึงตามสิทธิ์เดิม รวมสาขาตัวเอง ส่วน Super Admin ปลดล็อกได้ทุกสาขา ไม่สร้างรายการสิทธิ์ปลดล็อกแยก
- เมื่อบันทึกผลนับสำเร็จ สิ้นสุดช่วงปลดล็อกชั่วคราวเดิมและเริ่มรอบกำหนดนับใหม่ทันที แม้ยอดขาดหรือเกินและยังไม่มีผู้ตรวจ
- ใช้แบบคำนวณสถานะจากข้อมูลเดิม ไม่เก็บสถานะล็อกแยก ไม่ใช้งานตั้งเวลาสลับสถานะ และไม่มีขั้นตอนส่งคำขออนุมัติปลดล็อก
- เก็บการตั้งเวลาสองค่าที่กลุ่ม ส่วนเวลาปลดล็อกถึงเมื่อไร ผู้ปลด และเวลาที่กด เก็บในสมาชิกกลุ่ม `cash_count_alert_members` ซึ่งมีหนึ่งแถวต่อสาขาอยู่แล้ว ผู้มีสิทธิ์กดปลดล็อกโดยตรง ไม่เพิ่มตารางคำขอหรือตารางสถานะใหม่
- ล็อกเมื่อพ้นกำหนดนับรวมช่วงผ่อนผันและไม่มีช่วงปลดล็อกชั่วคราวที่ยังใช้ได้ เมื่อลบผลนับ ใช้ผลนับล่าสุดที่ยังเหลือหรือวันเข้ากลุ่มตามกติกาเดิมคำนวณใหม่
- การปลดล็อกเกินกำหนดไม่ยกเลิกล็อกระหว่างกำลังนับเงินจริง ใช้จุดป้องกันงานการเงินร่วมกันโดยแยกเหตุผล
- แต่ละกลุ่มมีสวิตช์ล็อกเมื่อเกินกำหนดนับเงิน ค่าเริ่มต้นปิดทั้งกลุ่มเดิมและกลุ่มใหม่ กลุ่มที่ปิดยังแจ้งเตือนตามเดิมแต่ไม่บังคับล็อก
- ปลดล็อกชั่วคราวได้เฉพาะตอนสาขาถูกล็อก ระหว่างช่วงอนุญาตแสดงเวลาคงเหลือและไม่ให้กดต่อเวลา เมื่อหมดเวลาและยังไม่นับสำเร็จจะล็อกและปลดรอบใหม่ได้
- ใช้หน้าต่างแจ้งเตือนร่วมเดิม เพิ่มสถานะถูกล็อกในรายการนับเงินและปุ่มปลดล็อกชั่วคราวประจำสาขาสำหรับผู้มีสิทธิ์ ผู้ไม่มีสิทธิ์เห็นข้อความติดต่อพร้อมชื่อผู้มีสิทธิ์ปลดล็อก มีแถบสถานะที่หน้าสาขาสำหรับเปิดหน้าต่างเดิม ไม่สร้างหน้าใหม่
- เมื่อแก้ชั่วโมงผ่อนผันก่อนล็อก ใช้ค่าใหม่ทันทีและคำนวณเงื่อนไขล็อกใหม่ ส่วนการแก้ชั่วโมงใช้งานหลังปลดล็อกมีผลกับการกดครั้งถัดไป ไม่เปลี่ยนเวลาสิ้นสุดของช่วงที่ปลดไว้แล้ว
- ล้างช่วงปลดล็อกชั่วคราวเดิมเมื่อย้ายสาขาไปกลุ่มอื่น นำออกจากกลุ่ม หรือปิดการล็อก ใช้เงื่อนไขของกลุ่มปัจจุบันเสมอ สาขานอกกลุ่มหรือกลุ่มที่ปิดการล็อกไม่ถูกล็อก

## โครงสร้างที่เลือก

ใช้กลุ่มเกณฑ์นับเงินเดิมและจุดป้องกันการเคลื่อนไหวทางการเงินของสาขา คงเหตุผลล็อกระหว่างนับและล็อกเกินกำหนดแยกกัน ใช้แนวหน้าจอและการตรวจสิทธิ์จากอนุมัติเบราว์เซอร์ แต่ไม่ใช้ตารางคำขอหรือสถานะอนุมัติเบราว์เซอร์เป็นสถานะล็อกสาขา เพราะขอบเขตและเงื่อนไขปลดล็อกต่างกัน

ข้อมูลช่วงปลดล็อกอยู่ในสมาชิกกลุ่มของสาขา การลบสมาชิกหรือลบกลุ่มจึงล้างช่วงอนุญาตไปด้วยตามอายุสมาชิกเดิม ส่วนปิดล็อกและบันทึกผลนับสำเร็จต้องล้างค่าโดยตรง สมาชิกที่ยังอยู่กลุ่มเดิมต้องคงวันที่เข้ากลุ่มและช่วงอนุญาตเดิมเมื่อแก้เวลา โดยการแก้ผ่อนผันยังมีผลทันทีตามข้อกำหนด

สูตรสถานะล็อก: อยู่ในกลุ่มที่เปิดล็อก และเวลาปัจจุบันถึงหรือเลยเวลาเริ่มล็อก และไม่มีช่วงปลดล็อกชั่วคราวที่ยังใช้ได้ โดยเวลาเริ่มล็อกคือ 00:00 น. ของวันถัดจากวันครบกำหนดตามเวลาไทย บวกชั่วโมงผ่อนผัน

## จุดเชื่อมที่ต้องทำให้ครบก่อนใช้งาน

1. **เริ่มนับกับงานค้าง:** ล็อกเกินกำหนดไม่เพิ่มข้อห้ามเข้า/เริ่ม/ส่งผลนับ แต่เงื่อนไขงานค้างเดิมยังมีผลทั้งในเครื่องและฐานข้อมูล ห้ามข้ามการตรวจเพื่อให้นับได้ หากงานค้างต้องเขียนยอดเพื่อแก้ ให้แสดงทางออกปลดล็อกชั่วคราว → ซิงก์/จัดการงานค้าง → เริ่มนับ และพาผู้ไม่มีสิทธิ์ไปติดต่อผู้ปลดล็อก ไม่รับประกันว่าเริ่มนับได้ทันทีทั้งที่มี blocker เดิม
2. **คิวซิงก์:** ใช้รหัสธุรกิจเฉพาะ เช่น `CASH_COUNT_OVERDUE_LOCKED` และคงข้อมูลในคิว ไม่เปลี่ยนทุก HTTP 409 ให้ retry ได้ ให้ลองงานที่ติดรหัสนี้ใหม่หลังปลดล็อกตามสิทธิ์เดิม โดยไม่ล้าง error อื่นหรือส่งงานซ้ำที่สำเร็จแล้ว
3. **สถานะกับหน้าต่างแจ้งเตือน:** ใช้ข้อมูลสถานะสาขาแยกจากการแสดง/รับทราบหน้าต่าง กดปิดแจ้งเตือนแล้วแถบล็อกยังอยู่ โหลดสถานะเมื่อเข้าสาขา เปลี่ยนสาขา กลับมาหน้าเว็บ หมดช่วงอนุญาต หรือ API ปฏิเสธด้วยรหัสล็อก ไม่เพิ่ม polling วนถี่อีกชุด และยังบังคับสิทธิ์ด้วยเวลาเซิร์ฟเวอร์เสมอ
4. **งานพร้อมกัน:** กำหนดลำดับล็อก transaction ให้ตรงกันระหว่างแก้/ลบกลุ่ม ปลดล็อกสาขา ส่งผลนับ และเขียนยอด ครอบคลุมสมาชิกก่อน/หลังแก้และสาขาที่เกี่ยวข้องทั้งหมด ตรวจสถานะซ้ำหลังได้ lock เพื่อป้องกันอนุญาตเก่ากลับมา การกดซ้ำต่อเวลา และ deadlock
5. **client เดิม:** การแก้กลุ่มที่ไม่ได้ส่งค่าใหม่ต้องคงสวิตช์และเวลาที่ตั้งไว้ การส่ง false โดยชัดเจนจึงปิดและล้างช่วงอนุญาต API ต้องแยก omitted/null/false ให้ชัด ไม่ใช้ค่า default ปิดทับกลุ่มเดิมระหว่าง rollout

หลักฐานเส้นทางเดิม: `src/components/cash-counts/CashCountModule.tsx` ตรวจคิวก่อนเริ่ม; `private.cash_count_start_blockers` ใน migration เดิมตรวจงานค้างฝั่งฐานข้อมูล; `src/lib/sync-response.ts` ไม่จัด 409 เป็น retryable; `src/hooks/useRubberWeightAlert.ts` ล้าง alert เมื่อรับทราบและตรวจตาม interval; `save_cash_count_alert_group` ใช้ advisory lock ของกลุ่ม ขณะที่งานการเงินใช้ `private.lock_report_locations`

## หลักตรวจรับเมื่อพัฒนา

- ตรวจเวลาฝั่งเซิร์ฟเวอร์และบังคับที่การเขียนข้อมูล ไม่อาศัยการซ่อนปุ่มหรือเวลาจากอุปกรณ์
- การปลดล็อกพร้อมกันต้องไม่ต่อเวลาโดยไม่ตั้งใจ และไม่ข้ามการล็อกขณะกำลังนับเงิน
- ทดสอบเส้นทางติดงานค้าง → ปลดล็อก → ซิงก์/จัดการงานค้าง → เริ่มนับ โดยไม่ปิดกติกางานค้างเดิม
- ทดสอบปิดแจ้งเตือนแล้วแถบล็อกยังอยู่ และคำตอบสาขาเดิมไม่ทับสาขาที่เพิ่งเลือก
- ใช้สอง connection ทดสอบปลดล็อกพร้อมส่งผลนับ/แก้กลุ่ม/ปิดล็อก และการโอนข้ามสาขาโดยไม่มี deadlock หรือการคืนช่วงอนุญาตเก่า
- ทดสอบ client เดิมแก้จำนวนวันโดยไม่ส่งค่าใหม่แล้วสวิตช์/ชั่วโมง/ช่วงอนุญาตไม่ถูกรีเซ็ต
- ทดสอบช่วงครบกำหนดก่อน/หลังเที่ยงคืนไทย จุดหมดเวลาพอดี ผลนับขาด/เกิน การลบผลนับล่าสุด การย้ายกลุ่มและแก้เวลา
- ทดสอบสิทธิ์สาขา ผู้จัดการระบบปลดให้สาขาตัวเอง และการแก้เงื่อนไขด้วยการนับเงินขณะถูกล็อก
