# ข้อสรุปการออกแบบนับเงินใหม่

ผู้ใช้ยืนยันขอบเขตและสั่งดำเนินงานครบทุก Phase แล้ว โค้ดใหม่ตรวจบน local; สถานะ Cloud/deploy แยกจากผลพัฒนา ดู cash-count-redesign-verification.md ข้อกำหนดทางธุรกิจที่ตกลงแล้วอยู่ใน CONTEXT.md หัวข้อการนับเงินเทียบยอดสะสม และ ADR 0079

## หน้าต่างแจ้งเตือนที่ผู้ใช้ยืนยัน

- ใช้หน้าต่างแจ้งเตือนร่วมกับเงินต่ำและน้ำหนัก มีปุ่มเลือกนับเงินแยกเฉพาะ
- ส่วนรายการ: `mt-4 max-h-[min(50dvh,24rem)] space-y-3 overflow-y-auto pr-1`
- ปุ่มเลือกนับเงิน: `focus-ring min-h-11 rounded-md border px-3 text-sm font-semibold border-black/15 bg-white`
- กลุ่มนับเงินแยกจากกลุ่มเงินต่ำและน้ำหนัก แต่ละสาขาอยู่ได้ไม่เกินหนึ่งกลุ่ม ตั้งระยะร่วมกัน 1–5 วัน
- Admin รับเฉพาะสาขาที่ได้รับมอบหมาย ผู้จัดการระบบและ Super Admin รับทุกสาขาที่เปิดใช้งาน User ไม่รับแจ้งเตือนนี้

## ประวัติเดิมที่ผู้ใช้ยืนยัน

- เก็บรายการนับเงินเก่าและถอดความผูกพันกับรายงาน การลบนับเงินไม่ลบรายงาน และการลบรายงานไม่ลบนับเงิน
- เลิกแสดงผลคาดการณ์และผลวิเคราะห์เดิม ไม่สร้างยอดระบบย้อนหลังเมื่อไม่มีหลักฐาน
- ใช้วันที่นับของรายการเดิมที่ยังไม่ถูกลบเป็นฐานตรวจครบกำหนดได้

## การแก้ไขหลังบันทึกที่ผู้ใช้ยืนยัน

- รายการที่บันทึกแล้วดูรายละเอียดและลบตามสิทธิ์เดิมได้ แต่แก้ยอดย้อนหลังไม่ได้ หากนับผิดให้ลบแล้วเริ่มนับใหม่ เพื่อไม่ผสมยอดระบบและรูปบัญชีจากคนละเวลา

## การบันทึกรูปที่ผู้ใช้ยืนยัน

- หากมีรูปบัญชีแต่บันทึกลง Google Drive ไม่สำเร็จ ต้องบล็อกการบันทึกรายการ
- ให้ลองบันทึกอีกครั้งโดยเก็บยอดนับและรูปไว้ ไม่บังคับถ่ายใหม่เพราะการอัปโหลดล้มเหลว ทั้งนี้รอบนับต้องยังไม่หมดเวลา

## การเปลี่ยนกลุ่มและเกณฑ์ที่ผู้ใช้ยืนยัน

- ใช้เกณฑ์ใหม่ทันทีเมื่อย้ายกลุ่มหรือเปลี่ยนระยะกำหนด โดยสาขาที่เคยนับใช้วันที่นับล่าสุดเดิม จึงอาจเข้าเงื่อนไขเกินกำหนดทันที
- สาขาที่ยังไม่เคยนับ เมื่อย้ายกลุ่มให้เริ่มระยะใหม่จากวันที่เข้ากลุ่มใหม่

## รอบแจ้งเตือนที่ผู้ใช้ยืนยัน

- นับเงินใช้รอบตรวจและการรับทราบร่วมกับแจ้งเตือนเงินต่ำและน้ำหนัก กดรับทราบแล้วปิดหน้าต่างทั้งรอบ
- รอบตรวจถัดไปเตือนซ้ำหากยังเกินกำหนด พร้อมจำนวนวันที่ล่าช้าล่าสุด
- ปุ่มตรวจแจ้งเตือนด้วยตนเองตรวจเงื่อนไขนับเงินด้วย

## การยืนยันผล OCR ที่ผู้ใช้ยืนยัน

- แสดงรูปคู่กับยอดที่ OCR อ่านได้ และบังคับให้ผู้ใช้ยืนยันว่า “ยอดตรงกับรูป” ก่อนบันทึกเมื่อใช้บัญชีธนาคาร
- ถ้ายอดไม่ตรงต้องถ่ายใหม่ ยอดเป็น readonly และทุกครั้งที่ถ่ายใหม่ต้องยืนยันใหม่
- กรณีไม่ใช้บัญชีไม่ต้องยืนยันผล OCR

## การเลือกยอดบัญชีที่ผู้ใช้ยืนยัน

- ใช้ยอดเงินคงเหลือของบัญชีก่อน หากหน้าจอมีเฉพาะยอดเงินที่ใช้ได้จึงใช้ยอดนั้น
- หากมีทั้งสองยอดและไม่เท่ากันให้ใช้ยอดเงินคงเหลือ ผู้ใช้ยังต้องตรวจยืนยันกับรูป

## การยืนยันตรวจสอบที่ผู้ใช้เพิ่ม

- เพิ่มปุ่ม “ยืนยันตรวจสอบ” ในรายการนับเงิน เป็นขั้นตอนไม่บังคับ ไม่จำเป็นต้องตรวจทุกรายการ พร้อมแสดงชื่อผู้กดยืนยันตรวจสอบ
- ใช้สิทธิ์เดียวกับแท็บจัดการระบบใน Admin ที่อ้างด้วยคลาส `focus-ring border-b-2 px-3 py-2 text-sm font-semibold border-leaf text-leaf`: Super Admin หรือ Admin ที่มี `canAccessSystemManager` ตาม `canManageSystemFeatures` ไม่ใช่ Admin ทุกบัญชี
- หลักฐาน: `src/components/admin/AdminContent.tsx` และ `src/lib/permissions.ts`
- ผู้ใช้ยืนยันว่าหลังตรวจสอบยังลบตามสิทธิ์เดิมได้ การตรวจสอบเป็นเครื่องหมายว่าใครตรวจแล้ว ไม่เพิ่มการล็อกหรือขั้นอนุมัติ

## PDF ใบนับเงินที่ผู้ใช้เพิ่ม

- พิมพ์ PDF หน้ากว้าง 80 มม. ตามรูปแบบเงินเดือนที่มีอยู่
- แสดงรายละเอียดเงินสด ยอดเงินในบัญชี และรายละเอียดเงินขาดหรือเกิน
- ด้านล่างมีชื่อผู้นับและผู้ตรวจ พร้อมบรรทัดให้เซ็น
- พิมพ์ได้แม้ยังไม่ได้ตรวจสอบ โดยเว้นชื่อผู้ตรวจให้เขียนเอง หากตรวจสอบแล้วแสดงชื่อผู้กดยืนยันใต้บรรทัดเซ็น
- ไม่มีช่องเหตุผลในฟอร์มหรือ PDF แม้ยอดขาดหรือเกิน โดยผู้ใช้แก้ไขข้อกำหนดเดิมที่เคยบังคับเหตุผลออกแล้ว

## ร่างคำสั่ง OCR สำหรับนำไปทดสอบ

อ่านยอดบัญชีธนาคารเดียวจากภาพถ่ายจอ เลือกยอดคงเหลือก่อน; ใช้ยอดใช้ได้เมื่อไม่มียอดคงเหลือ มองหาการ์ดบัญชีช่วงบน แต่อย่าเลือกจากขนาดหรือตำแหน่งอย่างเดียว ไม่อ่านยอดธุรกรรม วงเงิน เลขบัญชี หรือบวกยอดซ้ำ หากหลายบัญชี เลือกยอดไม่ได้ ยอดซ่อน หรือเลขไม่ชัด ให้ amount=null ห้ามเดา คืน JSON เท่านั้น: {"amount":"1234.56"|null,"kind":"balance"|"available"|null}

คำสั่งที่ใช้จริงอยู่ใน src/lib/server/cash-count-bank-ocr.ts ทดสอบกับภาพตัวอย่างหกภาพและภาพสังเคราะห์สามกรณีแล้ว ผลผ่านตามเงื่อนไข ไม่ใช่การรับประกันทุกภาพ

## ข้อแก้ไขล่าสุด — ขยายเป็นสี่บัญชี

ข้อจำกัด 0–1 บัญชี/หนึ่งรูปในข้อสรุปเดิมถูกแทนที่ด้วย 0–4 บัญชี ช่องละหนึ่งรูปตาม cash-count-multi-account-design.md ยอมให้บัญชี/รูปซ้ำ อ่านเฉพาะยอด ยืนยันรายช่อง อัปโหลดครบก่อนบันทึก และ PDF แสดงรายช่องพร้อมรวม
